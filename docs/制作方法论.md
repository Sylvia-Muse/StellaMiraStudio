# 作品目录 · 约定

一条视频一个文件夹，做完的东西不再散落在 data/debut 里。

## 目录结构

```
data/videos/
├── README.md                                  ← 本文件（总说明 + 索引）
├── 20261028_01_debut_live2d-showcase/         ← 出道视频（已发布）
│   ├── README.md                              这一条自己的说明
│   ├── meta.json                              标题/简介/标签/分区/发布状态
│   └── video.mp4                              成片（若体积大可只留 BV 号）
└── 20261028_02_slice01_alarm/                 ← 切片01（待发布）
    ├── README.md
    ├── meta.json
    ├── video.mp4
```

## 简介约定

**只有第一条（出道视频）写完整 staff**：Live2D 模型 / 服设 / 声线 / 剪辑企划。
之后的视频不再重复署名，只写本片自己的内容与必要说明（真实姓名类署名一次即够，反复写反而像模板）。

## 命名规范

`YYYYMMDD_序号_短名`，短名用小写字母、数字、连字符：

- `20261028_01_debut_live2d-showcase`
- `20261028_02_slice01_alarm`
- `20261102_03_voice-design-journal`

# 我做视频的各种方法（按能复用的程度排）

## 一、Live2D 逐帧渲染（主力方法）

**原理**：把 Live2D 模型放进一个网页（pixi.js + Cubism 4），用 Playwright 逐帧调用内部更新、逐帧截图，再合成视频。好处是**完全可控**——可以按音频波形驱动口型、按段落切表情、按镜头推拉，且同一帧号永远得到同一张图。

```
scripts/debut_v2.py      台词 → TTS → 音轨 + 时间轴(plan.json) + 口型包络(mouth.json)
scripts/debut_build.py   render（逐帧截图）/ mux（音轨 + 配乐混流）
data/debut/site/         渲染页面（1080×1920），含 __frame(i) / __probe / __modelRef 钩子
```

要点：
- `app.ticker.stop()` + `model.autoUpdate = false`，参数自己写，才能确定性
- 口型包络按 30fps 从音轨算 RMS，平滑后写进 ParamMouthOpenY
- **分段镜头**：每段给自己一个 scale/scale.y，帧间 lerp 0.10，切镜不硬跳
- 表情按段落切，讲猫耳时用「开关-兽耳」，讲真祖时用「表情-黑脸」
- 字幕每行 ≤13 字，用 `<br>` 硬切；幕起点 = 音频起点 +0.10s

## 二、字幕与口型的时间对齐

```
ffmpeg -af silencedetect=noise=-35dB:d=0.35   # 注意：输出在 stderr
```
- 用静音检测切分语音段落，比按字数比例切准得多
- 中文 TTS 语速约 4.7 字/秒（muse 音色实测），可先估算再校正

## 三、AI 出图（封面、表情包、素材）

```
scripts/img_gen.py       通用：--backend local|cloud
scripts/sticker_batch.py 表情包批量：出无字图 → PIL 叠字 → 方形裁切
scripts/debut_cover.py   封面：16:9 / 4:3 两版
```

要点：
- **本地**（`100.99.5.35:8211`，qwen-image Q4）做量产，单张约 42 秒；**云端**做交付级
- 让模型直接写中文会糊，**文字一律 PIL 叠**（Hiragino Sans GB，字号 12% 宽，白描边，顶部留 5.5%）
- 封面必须两种比例都能看：按窄的画幅排版，宽版才不会被裁
- 取帧做封面时，**记得裁掉烧进画面的字幕**

## 四、配乐

```
scripts/debut_bgm.py     v3：长音铺底（被指「太深沉」）
scripts/debut_bgm4.py    v4：120 BPM 拨弦琶音，C–G–Am–F，低音减半
```
纯 Python 合成（正弦 + 二次泛音 + 指数包络），不需要外部音源。判断“亮不亮”看频谱重心（centroid）：805Hz → 867Hz 的变化是能听出来的。

## 五、配音（TTS）

```
网关 127.0.0.1:11091 → qwen-audio-3.0-tts-plus，音色 rosy/hana/mira/muse
scripts/debut_revoice.py  重新生成某几条台词
```
- 每个音色有自己的“音高 + 语速”指纹，muse 是 304Hz / 4.70 字/秒
- 采样率参数可以填 24k/44.1k/48k，但**填多少都是上采样**，高频能量恒在 −39dB

## 六、唱歌 / 换音色

```
ACE-Step 1.5（本地，词曲人声一次出）→ UVR5 分轨 → RVC（训练过的音色模型）→ 混音
Seed-VC                   零样本快速对照（带宽 7.5kHz，会削掉气声）
```
要点：
- Seed-VC 的 `auto_f0_adjust=true` 会**整体降调**，女→女必须关掉，否则和伴奏错调
- 别用 base64 传音频（40 秒 → 5.8MB JSON 会 Broken pipe），用服务器本地路径，请求体 260 字节
- RVC 需要 10~20 分钟目标音色语料；**语料带宽决定模型上限**，TTS 语料做不出真高频
- ACE-Step 是**非确定性**的：同参数跑两次是两首歌，A/B 必须一次连跑多条

## 七、混音

```
[人声] highpass=f=70, volume=+1.5dB, 立体声化
[伴奏] volume=-4dB
amix=normalize=0 → loudnorm=I=-14:TP=-1.5 → alimiter=0.89
```
做完必查 `volumedetect`：峰值不超过 −0.5dB，否则会削波（Seed-VC 的输出就带 74 处削波）。

## 八、投稿（目前最不顺的一环）

- 标题/标签/简介/分区都能自动填，**只有封面必须人工**：B站要求走封面编辑器点「完成」，而那个按钮 `document.querySelector` 查不到
- 分区看 `tid_v2`，不要看 `tid`（旧码会误判成音乐·翻唱）
- Mac 上菜单栏 + 程序坞会挤掉窗口高度，投稿按钮滚不到 → 程序坞挪左侧，或用 JS 直接 `btn.click()`
- 简介约定：**只有出道那条写完整 staff**，后续视频只写内容

## 九、值得记住的坑

| 坑 | 表现 | 解法 |
|---|---|---|
| 单帧测试镜头没生效 | 截图看起来没推拉 | 插值是每帧 10%，单帧只走一步，要连续跑 |
| 表情段切换无过渡 | 生硬 | 用 lerp 或给 2~3 帧过渡 |
| 批量任务被中断 | 算到一半的图作废 | `nohup` + 断点续跑（跳过已存在文件） |
| 语料脚本死循环 | 整批跳过不报错 | 文件号要避开已存在文件，文本要按内容去重 |
| 跨聊天传公钥 | 一位大小写被改，指纹全错 | 走文件 + sha256 校验，只认指纹 |

# 十、MV 流水线（歌曲二创）

> 从「一首别人的歌」到「一条竖屏 MV」。以《world.execute(me);》为例，212 秒、6370 帧。

## 步骤

```bash
# 1) 取音轨（有授权的前提下）
#    官方源优先；B站官方账号的视频可用 playurl 取 audio 流（需登录 cookie）
py scripts/get_audio.py            # 拿 dash.audio 最高码率的 baseUrl，再 curl 下载

# 2) 歌词：官方 LRC 比 ASR 靠谱得多
#    网易云 API：https://music.163.com/api/song/lyric?id=<id>&lv=1&kv=1&tv=-1
#    ASR 只用来兜底核对，识别出的英文专有名词经常错

# 3) 分离人声（口型必须跟人声，不能跟整轨）
#    UVR5 服务：POST /v1/audio/separate_bin {audio, model:"inst_hq", stem:"vocals"}
#    ⚠️ 关键坑：口型包络若从整轨算，间奏和鼓点会让嘴巴乱动

# 4) 生成 plan / 口型 / 节拍包络
py scripts/mv_build.py             # 写 site/plan.json + mouth.json（人声）+ music.json（整轨）

# 5) 逐帧渲染（6370 帧 ≈ 29 分钟，3.7 帧/秒）
py scripts/debut_build.py render

# 6) 混流：粒子背景在这里叠，不在页面里画
py scripts/mv_mux.py out.mp4
```

## 设计要点

| 项 | 做法 | 为什么 |
|---|---|---|
| 口型 | 从**人声轨**算 RMS 包络 | 整轨会把嘴巴交给伴奏 |
| 身型 | 正弦摆动 + **节拍能量**（整轨包络） | 「身体跟音乐、嘴巴跟人」 |
| 表情 | 按时间轴分段（发懵→眯眼→惊喜→脸红→眼泪→脸红） | 一首歌的情绪弧线 |
| 镜头 | 每段一个 scale/y，帧间 lerp 0.10 | 副歌推近，间奏拉远 |
| 背景 | ffmpeg 后期 `gblur=sigma=18` + 22% 不透明度叠加 | 换背景不用重渲 6370 帧 |

## 录制法（推荐：直接用那个 HTML）

如果素材本身就是个「拖音频进去就动」的网页（比如 `demos/particle-mv.html`），
别逐帧渲染，**录它**：

```bash
py scripts/mv_record.py --out out.mp4
```

流程：起本地 http 服务 → 无头 Chromium 打开页面 → 用 `DataTransfer` 构造 drop 事件把音频喂进去
→ 点 START → 实时录制 → ffmpeg 贴回原音轨。

### 录制的两个坑

1. **录制尺寸必须等于视口尺寸**。设成 2560×1440 而视口 1920×1080 时，页面只画在左上角，
   其余是灰边——降采样后比原生更糊。1:1 录、crf 18。
2. **这类页面大多为 16:9 设计**。硬塞进竖屏 1080×1920 会又糊又挤。
   所以：**MV 类横屏、切片类竖屏**，别混。

## 两个坑（逐帧渲染法）

1. **旧 MV 录屏自带烧死的字幕**——拿它当背景会和自己做的字幕叠成两层。解法是强模糊，
   或者换不带字的素材。**取任何现成画面当背景前，先看它有没有内置文字。**
2. **歌词不能原样进公开仓库**。演示文件里的词要换成占位符（`♪`），时间轴保留——
   别人换成自己的词就能用，引擎照跑。
