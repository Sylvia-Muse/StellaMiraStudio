# 《红昭愿》水墨 MV · 最该改的 3 处（带时间点和参数）

对象：`data/videos/20261101_06_hongzhaoyuan-mv/mv_art_full.mp4`
（171.58s / 1920×1080 / 30fps）与样片 `mv_art_scroll_clip.mp4`（40s，= 歌内 16–56s）。

> **时间换算**：样片 t = 歌内 T − 16。下文两个都给。
> **"倍数"一律是相对当前 `cameraAt(t)` 输出的 zoom**，不写死绝对值——
> 因为 `framingFor()` 会按行宽反算 zoom，写死绝对值下次改排版就崩。

## 一句话诊断

技术层面没有硬伤，**问题是"没有事件"**。用 `scripts/vshot_report.py --profile mv` 实测：

```
171.5s 内"取景变化点"只有 12 个（每 14.3s 一次；MV 应每 2–4s 一次）
13 段"一个取景"的时长：
  49.8s | 34.2s | 17.1s | 16.9s | 14.4s | 8.3s | 6.0s | 5.9s | 5.2s | 4.4s | 4.2s | 2.9s | 2.2s
  ↑ 最长的三段 = 101.1s = 全片 59%
```

**59% 的时间里镜头一次都没换过取景。** 观众说的"一个镜头里一个字变来变去"，
说的就是这三段。下面三处就是这三段，参数直接可填。

其余全局问题（响度 / 字幕位置 / 纸纹硬边 / 顶边裁切）在文末 G1–G5。

## 全局项（一改就见效，不占"3 处"名额）

### G1 景别动态范围 1.36× → ≥ 2.5×
样片 40s 全程 13.9%–18.9%，**只有一档**。不用改 `framingFor()`，
只要在 `ROWS.forEach` 生成关键帧那一步给 `zz` 乘一个档位系数：

```js
const DYN = { 前奏: 0.85, 主歌: 1.00, 副歌: 1.18, 间奏: 0.80, 结尾: 0.62 };
const zz = f.z * (sec.name === '副歌' ? 0.97 : 1.0) * DYN[sec.name] * edge(row);
// edge(row)：每段最后一句 ×1.55（推到特写），每段第一句 ×0.72（拉回全景）
```
60 句 / 约 12 段 → 每段一次"全景→特写"往返，景别范围立刻上 2.5× 以上。

**目标分布**（用 `vshot_report.py` 验）：

| 景别 | 主体带高占比 | 目标时长占比 |
|---|---|---|
| 特写 | 38–52% | 15% |
| 近景 | 25–38% | 25% |
| 中景 | 16–25% | 25% |
| 全景 | 8–16% | 25% |
| 远景 | ≤ 8% | 10% |

### G2 顶边裁切：样片 162 帧采样里 111 帧（69%）有半截字贴着画面顶边
实测 `y0=0.000`（墨迹贴到画面最上一行），被切的那条带有 8.3% 高（约 40% 被截），
最深的一帧被切掉 22.8% 画面高。

最省事的改法（1 行，不动取景几何）——**顶边软淡出**：
```glsl
float yScr = uv.y;                             // 0 = 顶边
alpha *= smoothstep(0.000, 0.075, yScr);       // 6–8% 过渡带
```
要做几何修正：`framingFor()` 里 `halfH = 0.5/z + GLYPH*0.55`
改为 `halfH = (0.5 - 0.06)/z + GLYPH*0.55`（顶部禁区 6%，与左右 6% 一致）。

### G3 纸纹 clamp 造成的矩形硬边（随镜头移动）
实测每帧都有一条硬横向色阶：y = 0.067 与 0.30（t=2s）→ 0.24（t=15s）→ 0.20（t=40s），
振幅 **4–12 / 255**。成因：`paper = texture(uPaper, w * 1.35 * uPaperScale)`，
`w` 是世界坐标，镜头一推就越过 paper.png 的 uv [0,1] 被 `CLAMP_TO_EDGE` 夹成平板。

```glsl
// 纸纹固定在屏幕（推荐）：它本来就是"这张屏幕上的纸"，不该跟镜头跑
vec3 paper = texture(uPaper, fract(uv * 2.2 + vec2(uTime*0.004, uTime*0.002))).rgb;
```
外加 `gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S/T, gl.REPEAT)`。
验收：清单 B3 的内联脚本从 `FAIL` 变 `PASS`。

### G4 响度 −11.80 LUFS / TP +0.05 dBTP → −14.0 / ≤ −1.0
整片已经贴到 0 dBFS（2 个音频块），转 AAC 后必然出现撕裂。
```bash
~/bin/ffmpeg -y -i mv_art_full.mp4 -c:v copy \
  -af "loudnorm=I=-14:TP=-1.5:LRA=11:print_format=summary" \
  -c:a aac -b:a 192k mv_art_full_norm.mp4
```
LRA 从 2.90 提到 ≥ 3.0 的办法不是压得更狠，而是在 `loudnorm` 之前让副歌（58–86s）
比主歌高 1.5–2.0 dB。

### G5 字幕底边距 7.8% → 12%
现状 `#lyric{ bottom: 74px }`，字号 52px → 字幕占画面 6.9%–11.7%，
整个落在 B 站进度条/弹幕框会盖住的底部 8% 带里。
```css
#lyric{ bottom: 130px; }   /* 1080p 下 = 12.0% 底边距，字幕占 12.0%–16.8% */
letter-spacing: .10em;     /* 从 .16em 收窄：8 个字从 25% 画宽收到 23% */
```

# 附录 · 实际改了什么（P0 + P1 执行记录）

> 本节记录**已经落到代码里**的改动，以及"用哪个数字证明它变好了"。

## 0. 改前先补工具：原来的"取景变化点"量错了

`vshot_report.py` 的取景检测是**像素代理**——它看"主体带高 + 墨迹重心 + 画面亮度"。
问题：**"笔在写"本身就会让重心右移、让亮度下降**，所以它分不清"镜头动了"和"字长了"。

因此新增 `scripts/vcamera_report.py`：直接读页面里的 `cameraAt(t)` 路径
（与渲染逐帧同一套插值公式），量的是相机本身。

用它重新量改前的片子，**真实数字和我上一轮报的不一样，以本节为准**：

| 指标 | 像素代理（上一轮报的） | 相机路径（真实） |
|---|---|---|
| 最长一个取景 | 49.8s | **18.8s**（47.2–66.7s 那段空档） |
| 取景变化点 | 12 个 | 127 个（0.74 次/秒） |
| 景别动态范围 | 1.36×（只量了 40s 样片） | **1.47×**（14.1%→20.7%） |

> 49.8s 那个数是"墨迹量不变"造成的误判：那段里相机其实在跟着行慢慢走（cy 每行 +0.43），
> 只是画面的**墨水总量**没变，像素代理就以为没动。抱歉，这条我上次报错了。

## 1. 根因（比"一个镜头太长"更具体）

```
歌词行的时间分布：47.55 → 66.05 有 18.5s 空档；81.05 → 100.20 有 19.2s 空档
```
这两段是**纯器乐间奏，没有歌词行**。而 v1 的相机关键帧是 `ROWS.forEach` 逐行生成的——
没有行 = 没有关键帧 = 相机原地不动。**这才是 18.8s 死区的真正原因**，不是"镜头设计得太长"。

附带发现一个真 bug：v1 结尾手写的 `pushKey(163.0, …, 0.16)` / `pushKey(168.4, …, 0.070)`
和自动生成的行关键帧（164.28 / 164.44 / 169.39）**互相打架**——
拉到 0.16 又被弹回 0.85，拉到 0.070 又弹回 0.878，**最后 9 秒在剧烈往返抽搐**。

## 2. P0-1 破死区：镜头 v1 → v3

三条设计原则（写进代码注释了）：

| 原则 | 为什么 |
|---|---|
| **取景事件 = 快速到位（0.38s）+ 停住** | 慢漂移在观众那儿等于没动，量也量不出来 |
| **空档里没行关键帧，整段写显式序列** | 不会和自动行关键帧打架 |
| **段落边界按"第几个 section"判断，不按名字** | manifest 里连续两个「主歌」是两段，按名字会把它们粘成一段，边界强调全丢 |

具体改动：

1. **前奏** 加 4 个取景点（0/2.3/4.3/6.3/9/12/14.6s，跟着「红昭愿」三个字写）。
2. **每行两个取景** `open` / `close`：起笔用 `open`（跟随行宽；段首再 ×0.56 拉成全景），

## 3. P0-2 纸纹硬边：真因不是"没开 REPEAT"

上一轮我判断"`CLAMP_TO_EDGE` 夹出的边"，**判断错了一半**：
`_load('art/paper.png', true)` 本来就是 `REPEAT`。问题在 **`paper.png` 不可平铺**——
REPEAT 在 uv 整数边界处把右边缘直接接上左边缘，产生一条**值不连续的硬缝**，
随镜头扫过画面。所以修法不是"改 REPEAT"，而是：

```js
const wrap = (repeat === 'mirror') ? gl.MIRRORED_REPEAT : (repeat ? gl.REPEAT : gl.CLAMP_TO_EDGE);
this.paperTex = await this._load('art/paper.png', 'mirror');
```

`MIRRORED_REPEAT` 在边界处左右镜像，**值连续**，接缝消失，且不需要重做贴图。

验证方式：把画面上所有的字关掉（`window.__flags = {noMasks:true, noLive:true, noBloom:true}`），
只渲纸面，然后量"相邻行中位亮度的孤立台阶"。

| | 硬边处数 | 最大台阶 |
|---|---|---|
| 改前 t=2/15/40s | 22 / 57 / 46 | 4.0 / **14.0** / 9.8 |
| 改后 t=2/15/40/95s | 7 / 10 / 26 / 19 | 3.2 / 3.8 / 4.0 / 3.8 |

**最大台阶 14.0/255 → 4.0/255（−71%）**，剩下的 3–4 级是纸纹本身的梯度，不是缝。

## 4. P1 做了什么

### P1-a 响度（整片 −11.33 → −14.04）


### P1-b 字幕底边距 7.8% → **13.1%**
```css

```

### P1-c 暗部面积 0.5% → **2.8%**（中位）

### P1-d 顶边裁切：四边软淡出
```glsl

      * smoothstep(0.000, 0.050, 1.0 - uv.x);
```
> 注意方向：本项目 `uv.y = 1` 才是**顶边**（世界 y 向上、屏幕 y 向下）。

## 7. 两个"改出问题又改回来"的坑（留给下次）

### 7.1 朱砂层原来完全没走边沿淡出
加完四边淡出后，`check_overflow` 仍报 12/80 帧越界。查下来：边沿遮罩只乘到了 `dens` 上，
而朱砂是**另一条路径**——`float red = clamp(dRed * 2.6, 0, 1)` 直接混进 `col`，
**从头到尾没有边沿遮罩**。红字因此一直压到画面边缘。改成：

```glsl
float edgeMask = smoothstep(...)...;
dens *= edgeMask;
float red = clamp(dRed * 2.6, 0.0, 1.0) * edgeMask;   // ← 这一行是关键
```

### 7.2 出画帧数 1 → 9，但深度 0.62% → 0.52%（**未完全达标，这是我的取舍**）
`check_overflow.py` 的判据是「**≤2 帧 且 越界 < 1%**」。现在是 **9 帧 / 0.52%**：
深度更浅（10px @1920，肉眼看不出），但帧数超了。

原因：段首 ×0.56 的"全景"让更多行同时入画，长行的两端自然更靠近画面边。
已经做过的缓解：左右淡出 5%→7.5%、朱砂补遮罩、`fitOpen()` 按最终 zoom 重算并集。

**要把它压回 ≤2 帧，二选一（都得重渲 8 分钟）：**
1. 左右淡出再放到 **10–12%**；
2. `fitOpen()` 的并集宽度上限从 `0.86` 收到 `0.80`（回到 v1 的原始安全区），
   代价是段首全景收窄一点、景别动态范围大概掉到 2.3× 左右。

我选了"保留景别动态范围、接受 9 帧的 0.3–0.52% 越界"——因为 0.52% 是 10 个像素的
半透明墨；而 2.5× 的景别是这次改片的主目标。

### 7.3 越界到底有多淡：alpha 证据（`check_overflow.py` 已加这项输出）

"越界 0.52% 画面宽"是几何量，说不清那点墨是"淡影"还是"实墨"。所以对越界的那几列，
额外统计**每列最暗像素的 alpha 等效值 = (255 − gray) / 255**：

| 帧 | 越界列数 | 中位 alpha | 均值 | 最暗 |
|---|---|---|---|---|
| 10.0s | 12 | 0.369 | 0.368 | 0.396 |
| 10.5s | 11 | 0.369 | 0.363 | 0.380 |
| 15.5s | 6 | 0.357 | 0.355 | 0.373 |
| 16.0s | 8 | 0.357 | 0.354 | 0.373 |
| 16.5s | 8 | 0.357 | 0.353 | 0.373 |
| 35.0s | 7 | 0.353 | 0.351 | 0.365 |
| 35.5s | 6 | 0.353 | 0.350 | 0.361 |
| 36.0s | 5 | 0.345 | 0.347 | 0.357 |

- 15.0s 一帧在**原分辨率**下其实没有越界（960 宽抽帧的 2×2 平均会把它算进去）。
- **中位 alpha = 0.357，最暗 0.396**。
- 判据是"中位 < 0.35 且无任一帧 > 0.60"：**实墨红线（0.60）差得很远，但 0.35 差 0.007 没过。**

> 注意测量口径：分析分辨率是 960×540，**下采样会把 2×2 平均掉**，同一批帧在 960 宽下
