## A. 镜头语言

### A.1 景别：用"主体高度占画面高的比例"当唯一标尺

不要用"特写/近景"这种词沟通，**用百分比**。判据永远是可测的。

**16:9 横屏（人物 / 单一主体）** `【经验判断】`

| 景别 | 主体高度 / 画面高 | 主观感受 | 用在哪 |
|---|---|---|---|
| 大特写 ECU | 0.75–1.00 | 压迫、情绪顶到脸上 | 副歌最高点、一句词的重音 |
| 特写 CU | 0.50–0.75 | 亲密、专注 | 主歌情绪句 |
| 近景 MCU | 0.36–0.50 | 默认谈话景 | 口播 / 叙事主镜头 |
| 中景 MS | 0.22–0.36 | 有环境、信息多 | 交代场景 |
| 全景 FS | 0.10–0.22 | 冷静、疏离 | 段落开头、留白 |
| 远景 LS | 0.03–0.10 | 情绪沉降 | 前奏、间奏、结尾 |

**9:16 竖屏（Live2D 人物）** `【经验判断】`
竖屏天然"人物占满"，同一档要整体上调，否则人物会显得小、手机上看不清表情：

| 景别 | 人物高度 / 画面高 | 备注 |
|---|---|---|
| 脸部特写 | 0.85–1.00 | 只留眼睛到下巴 |
| 头肩 | 0.62–0.85 | 竖屏最常见的"说话景" |
| 半身 | 0.42–0.62 | 能带手部动作 |
| 全身 | 0.28–0.42 | 展示服装/动作 |

`【实测·本片】` 我们的竖屏切片 `slice03` 人物高度 60.3–63.4% = 头肩偏半身，**合适**。
MV 40s 样片里的文字主体 13.9%–18.9%，按 16:9 表是"全景"，且 **40 秒里只在 1.36× 的
范围内浮动**——这才是问题（不是"选错了景别"，是"没有别的景别"）。

**硬规矩（直接写进 build 脚本的断言）**
1. 全片景别动态范围 `p90/p10 ≥ 2.5×`（MV）/ `≥ 1.5×`（竖屏口播）。
2. 相邻两个镜头的景别档**不得相同**（同档就连成一镜）。
3. 任意连续 20s 内，必须至少出现 3 个不同的景别档。
4. 人像（Live2D）在 16:9 里**不要低于 0.30**——低于 0.30 表情信息全丢，只剩一个色块。
   `【经验判断】` 我们的 40s 样片全程 0.14–0.19，等于把所有表情信息都扔了。

### A.2 运镜：幅度 × 时长 × 缓动，三件套

**可感知下限**：一次运镜如果 `幅度 / 时长 < 1.0 %/s`（画面线性尺度每秒变化 <1%），
观众**看不见**，等于没做。`【经验判断】`

由此得到唯一有用的公式：

```
幅度(%) / 时长(s) >= 3      # 想要"看得出来"的运镜
幅度(%) / 时长(s) in 1..3   # 呼吸，只能当底噪，不能当事件
幅度(%) / 时长(s) <  1      # 无效，删掉
```
其中 `幅度 = |zoom_after/zoom_before - 1| × 100`（zoom 越大画面越"近"）。

**推 / 拉（dolly）** `【经验判断】`

| 用途 | 幅度 | 时长 | 等效 `%/s` | cubic-bezier |
|---|---|---|---|---|
| 卡点快推（鼓点上） | 12–25% | 0.25–0.50s | 40–60 | `cubic-bezier(.33,0,.20,1)` |
| 常规推镜 | 10–20% | 1.0–2.0s | 8–15 | `cubic-bezier(.33,0,.20,1)` |
| 情绪慢推 | 6–12% | 3.0–6.0s | 1.5–3 | `cubic-bezier(.25,.10,.25,1)` |
| 段落呼吸 | ≤ 5% | ≥ 8s | <1 | `cubic-bezier(.45,0,.55,1)`（≈正弦） |
| 甩镜 whip | ≥ 40% | 0.10–0.20s | ≥300 | `cubic-bezier(.20,.80,.30,1)` + 方向模糊 6–10px |

**摇 / 移 / 跟（pan / truck / track）** `【经验判断】`
- 速度区间：`0.3–0.8 × 画面宽 / 秒`（即一秒扫过 30%–80% 画面宽）。
  低于 0.15 宽/秒 看不出在动；高于 1.2 宽/秒 会糊。
- 缓动：`cubic-bezier(.40,0,.20,1)`（快起慢收）；超长横移用"线性 + 首尾各 12% 时长做 ease"。
- 横移的"从哪儿到哪儿"比速度重要：起点必须落在三分线一侧，终点落在另一侧，
  **位移 ≥ 画面宽的 1/3** 才叫"移"，否则叫"抖"。`【经验判断】`

**升降（crane / 垂直）**
- 速度 0.2–0.5 × 画面高/秒；竖屏比横屏更容易晕，取区间下沿。

**缓动曲线速查**（`cubic-bezier(x1,y1,x2,y2)`，可直接喂 CSS / 自研插值器）
```
快起慢收（推、移的默认）      cubic-bezier(0.33, 0.00, 0.20, 1.00)
慢起快收（甩出去）            cubic-bezier(0.55, 0.00, 0.90, 0.30)
两端缓（呼吸、循环）          cubic-bezier(0.45, 0.00, 0.55, 1.00)
线性（等速横移、字幕滚动）    cubic-bezier(0.00, 0.00, 1.00, 1.00)
带回弹（弹入，慎用）          cubic-bezier(0.34, 1.56, 0.64, 1.00)
```
`【参考】` 缓动曲线的一般设计原则见 [Easing — Design System](https://www.galaxus.ch/designsystem/foundations/motion/easing-design)；
上面具体数值是 `【经验判断】`。

**我们现在的实现对照**：`mv-art.html` 的 `cameraAt()` 用
`u = mix(u, smooth(u), 0.75)`（smooth = smoothstep），等价于一条略偏线性的
两端缓曲线——**曲线本身没问题**，问题是幅度：主歌段 zoom 0.94→1.02，
40 秒里总共 8.5%，`%/s ≈ 0.2`，正好落在"无效"区。

### A.3 一个镜头多长 / 什么时候该切

**镜头长度** `【经验判断】`（参考 [Cinemetrics](https://cinemetrics.uchicago.edu/) 一类的
平均镜头长度统计，剧情片 4–6s、MV 2–3s；我们取更短的 MV 侧）

| 内容 | 单镜头时长 | 硬上限 |
|---|---|---|
| MV 主歌 | 1.6–3.2s | 4.0s |
| MV 副歌 | 0.8–1.6s | 2.4s |
| 竖屏 vlog / 切片 | 2.0–4.0s | 6.0s |
| 情绪留白（前奏/间奏/尾） | 2.0–4.0s | 4.0s，且必须带 ≥15% 运镜 |

**"该切了"的四条判据**（满足任意一条就切）
1. 这一句唱完了（下一句歌词开始）→ 切。
2. 画面里的"事件"停了 > 1.5s（笔写完了、动作结束了）→ 切。
3. 同一个取景已经持续 > 4s，且这 4s 里画面重心没移动 > 5% 画面宽 → 切。
4. 音乐进入新段落（主歌→副歌、进鼓）→ **必须**切或做一次 ≥25% 的运镜。

**不要切的三种情况**
- 正在写字/正在说话且信息还没给完。
- 切点落在音符中间（不在拍上也不在字上）。
- 连续两个镜头景别一样（等于没切，只是抖了一下）。

## B. 节奏与剪辑

### B.1 卡点三法

| 方法 | 做法 | 参数 | 用在哪 |
|---|---|---|---|
| **硬切卡点** | 画面在拍点上直接换 | 切点对齐到 `beat_time ± 1 帧`（30fps 下 ±33ms，听感上已经够准） | 副歌、鼓组进入、drop |
| **动作卡点** | 画面里的**动作完成瞬间**落在拍上（笔尖收笔、墨点炸开、人物转头） | 动作的"完成时刻"（不是开始时刻）对齐拍点，提前量 = 动作时长的 100% | 主歌、有叙事的段落 |
| **情绪卡点** | 不跟拍，跟**段落**：乐句/sub-phrase 边界切 | 4 拍（1 小节）或 8 拍为界 | 慢歌、留白段、结尾 |

`【经验判断】` 判断标准很简单：**把画面关掉只听歌，你能哼出来的那个"呼吸口"就是情绪卡点的位置。**

`【参考】` 卡点方法论的一般性整理见
[music-beat-sync 笔记](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/music-beat-sync.md)。

### B.2 镜头长度 × BPM：那条"每 N 拍"的公式

```
一拍时长  beat = 60 / BPM                (s)
N 拍一换  shot = N × 60 / BPM            (s)
反查      N   = shot × BPM / 60          (必须在 1..16 之间，最好取 2/4/8)
```

**《红昭愿》实测 BPM = 114.9（beat 0.522s，来自 `manifest.json` 的 319 个 beat）**`【实测·本片】`

| N（拍） | 镜头时长 | 适用 |
|---|---|---|
| 1 | 0.52s | 副歌高潮、"快切段落"，最多连用 4 个 |
| 2 | 1.04s | 副歌常规 |
| **4（1 小节）** | **2.09s** | **主歌常规，最稳的选择** |
| 8（2 小节） | 4.18s | 前奏/间奏/情绪段 |
| 16 | 8.35s | 只用于结尾拉远 |

**我们现在的问题**：60 句词 / 171.58s = **每 2.86s 换一次取景**
→ `2.86 × 114.9 / 60 = 5.48 拍`。**不是整数拍**，所以听感上是"卡不上拍"的。
改成 4 拍（2.09s）或 8 拍（4.18s）立刻就"在拍上"了——这是几乎零成本的改动。

**更硬的证据**：60 句词的**行首**到最近拍点的距离，中位 **0.118s**、最大 0.254s，
只有 **18%** 的行首落在拍点的 ±1 帧内（30fps）。`【实测·本片】`

> 说明"跟歌词切"和"跟拍切"是**两套时钟**，天生对不上。必须显式二选一：
> - 走**情绪卡点**（跟歌词）→ 就不要假装在卡拍，把转场做"软"（叠化/动作），
>   别指望观众数出拍子。
> - 走**节奏卡点**（跟拍）→ 换景时刻必须 `snap_to_beat(t, BEAT, 0.12)`
>   （吸附到 ±0.12s 内最近的拍），并且接受"一句词可能横跨 2–3 个镜头"。
>
> 一首歌只能选一种。**我们现在的状况是两者都没选**——按歌词切，但间距又不是整拍。

### B.3 静与动的配比

`【经验判断】`，全部可用 `vshot_report.py` 直接量：

| 指标 | 判据 | 全片实测 | 40s 样片 |
|---|---|---|---|
| 静止段占比（帧差 < 0.8/255 的 ≥1s 段） | **≤ 18%** | 19% ❌ | 8% ✅ |
| 单段静止上限 | **≤ 2.5s** | **12.7s** ❌ | 1.8s ✅ |
| 取景变化点密度 | 每 10s ≥ 2 次 | **0.7 次** ❌ | **0 次** ❌ |
| 最长"一个取景" | **≤ 12s** | **49.8s** ❌ | 39.9s ❌ |

**为什么不能 100% 都在动**：眼睛的"变化检测"会疲劳，持续运动反而读不出重点。
工业做法是 **3:1 到 2:1 的动/静比**，且"静"必须和"动"**交替**，不能攒在开头/结尾
（我们现在正好攒在开头 14.4s、间奏那一段 34.2s、结尾 49.8s——全片最长的三段"不动"
都堆在了观众最容易走的位置）。

## C. 转场

### C.1 五种转场与使用条件

| 转场 | 时长 | 什么时候用 | 什么时候别用 |
|---|---|---|---|
| **硬切** | 0 帧 | 默认。同一时空、同一主体、时间连续 | 两个镜头景别相同（等于抖一下） |
| **叠化 dissolve** | 8–20 帧（0.27–0.67s@30fps） | 时间跳跃、地点跳跃、情绪软过渡 | 同一个物体在动的时候（会糊成一坨） |
| **划像 wipe** | 12–24 帧 | 有明确方向性（左右/上下的空间关系） | 无方向语义时显得土 |
| **遮挡转场**（whip pan / 走过镜头 / 墨点糊满屏） | 6–12 帧 | **动作连续**：前一镜的动作出画，后一镜同方向入画 | 两边动作方向对不上时 |
| **匹配剪辑**（形状/运动/颜色匹配） | 0 帧 | 想表达"这两件事是一回事" | 找不到真的匹配点时不要硬凑 |

`【经验判断】` 时长数值是按 30fps 报的帧数，与分辨率无关。

### C.2 "同一元素连续演化"（墨点 → 字 → 墨点）该用什么

这是我们的招牌镜头，也是唯一**不该用现成转场**的地方。规则：

> **元素连续演化 = 0 帧转场。变化必须发生在同一个连续场里，不要叠化、不要切。**

`【经验判断】` 具体可用的三档，按"变化量"选：

| 变化量 | 做法 | 参数 |
|---|---|---|
| 小幅（墨点 → 字） | 密度场过渡，共用一个浮点场 | 过渡时长 = 该字书写时长 × 0.25；不要额外加淡入淡出 |
| 中幅（一行字 → 整卷） | **同场变焦**（dolly），不切 | zoom 变化 ≥ 2.5×，时长 1.2–2.0s，`cubic-bezier(.33,0,.20,1)` |
| 大幅（这一句 → 完全不同的画面） | 墨点"吃掉"上一帧再"吐"出新画面 | 吃：0.55s，墨团半径 0 → 1.15×对角线，alpha 0→0.95；吐：0.70s，反向；中间留 0.10s 全黑/全墨 |

**必须避开的坑**：`【实测·本片】` 我们现在的换行过渡是
"行末 12% 内平滑移到下一行"（`mv-art.html` 的 `pushKey(row.t + 0.88*dur, ...)`），
时长 0.25–0.5s、位移 ≈ 0.43 世界单位 ≈ 40% 画面高 —— 幅度够了，但因为**全片每句都这样**，
它就退化成了"呼吸"而不是"事件"。**同样的转场用 60 次 = 没有转场。**

## D. 构图与版式

### D.1 三分 / 中心 / 留白

**横屏 16:9** `【经验判断】`

| 构图 | 参数 | 适合 |
|---|---|---|
| 三分法 | 主体中心落在 x ∈ {0.333, 0.667} ± 0.04，y ∈ {0.333, 0.667} ± 0.04 | 有人物、有环境的镜头 |
| 中心构图 | 主体中心 x ∈ 0.50 ± 0.02 | 仪式感、对称、封面、标题卡 |
| 大面积留白 | 主体占画面面积 ≤ 15%，且**留白集中在一侧**（不是四边均匀） | 水墨、情绪、字幕画面 |

**我们的实测** `【实测·本片】`（MV 40s 样片，主体带水平重心）：

```
cx  p5 = 0.244   p50 = 0.419   p95 = 0.785   范围 0.157–0.795
竖屏切片 slice03：cx 恒在 0.50 ± 0.02（人物居中）
```

所以两件事要分开说：
1. **MV 的重心确实在动**（0.24–0.79），但那是"这一行有几个字 + 每行 0.05 的错落"
   算出来的**排版副作用**，不是构图决策——没有一次是"刻意把重心放到三分线上"
   （0.333 / 0.667 各只出现过零星几帧）。这种"随机游走的居中"看起来最廉价。
   判据：重心落在 `0.333±0.04` 或 `0.667±0.04` 的帧应占 **20%–40%**。
2. **竖屏切片是 100% 中心对称**。中心构图不是错，错在**一部片子里 100% 都是它**。
   判据：全片"主体重心偏离 0.50 超过 0.06"的帧应占 **30%–60%**。

**竖屏 9:16 的差异** `【经验判断】`，参考
[竖屏构图指南](https://smoothyedit.com/blog/editors-field-guide-vertical-video)
1. 竖屏不能用三分法的**交点**，要用**上下两条水平线**（y = 0.33 / 0.67）：视线是上下扫的。
2. 人物头顶留白 **6%–10%**（低于 6% 压抑，高于 12% 显得矮）。
3. 底部 **18%–22%** 是字幕+UI 区，主体（脸）不要放进去。
4. 横屏那套"左右留白"在竖屏无效——竖屏的空在上下。

### D.2 字幕排版（可直接写进 CSS / 绘制代码）

`【实测·本片】` + `【经验判断】`，括号里是我们的现状。

### D.3 中文字幕的坑（每条都能变成一条检查项）

1. **标点不出现在行首**：`，。、；：？！）】」』` 不能是下一行的第一个字。
   断行时用 `禁止行首` 集合，遇到就往前借一个字（`orphan` 规则）。
2. **标点不出现在行尾**：`（【「『` 不能是行末。
3. **不要在句中断行**：中文歌词按**乐句**断，不按字数断。
   `【实测·本片】` 我们的 `check_lyrics.py` 已经保证"画面字幕 == manifest"，
   但没有检查"断行是否落在乐句边界"——目前 8 字一折（`MAX_PER_ROW = 8`）是**按字数硬折**，
   会把"眉目刚烈拟作妆嫁"这种完整句式切开。**建议改成按逗号/乐句优先，字数兜底。**
4. **禁用英文省略号/半角标点**：`...` → `…`，`,` → `，`。全角半角混排会跳字距。
5. **字幕与画面元素打架**：字幕 bbox 上方 4% 高度内不应有主体。
   `【实测·本片】` MV 0% 冲突 ✅；竖屏切片 100% 冲突（字幕压在裙子上）——这是审美选择，
   但**必须知道自己在做**，且要在字幕后面加 0.35 黑/白描边或 8% 不透明底片保证可读。
6. **字幕不能被画面里的字"抢戏"**：MV 里我们同时有"毛笔写的歌词"和"印刷体字幕"，
   两者内容完全一样 → **信息冗余就会显得低效**。要么去掉字幕（让毛笔字承担），
   要么让毛笔字只写**关键词**、字幕给全句。

## E. 调色与质感（水墨 / 低饱和）

### E.1 实用参数区间（255 制，`vtone_check.py` 的判据同源）

`【经验判断】` + `【实测·本片】`

| 参数 | 水墨/低饱和参考区间 | 说明 | 我们 MV 实测 |
|---|---|---|---|
| 黑位 P0.5 | **20–45** | 画面里必须真的有一点黑，否则"纸"和"墨"分不开 | 101 ❌ |
| 白位 P99.5 | **228–245** | 纸不能到 255（会死白、丢纸纹） | 233 ✅ |
| 中位 P50（纸的亮度） | **200–232** | 低于 200 纸发脏，高于 235 发灰 | 224 ✅ |
| 动态范围 P99.5−P0.5 | **≥ 150** | <120 就是"灰蒙蒙" | 132 ❌ |
| 暗部面积（灰度<100 占比） | **≥ 2%**（每帧） | 这就是"墨够不够重" | 0.5% ❌ |
| 色温（R−B 差） | **+8 ~ +22**（暖纸） | 冷纸会把水墨推向"阴间" | +21（224,216,203 → R−B=21）✅ |
| 平均饱和度 S | **≤ 0.18**（水墨）/ **≤ 0.35**（人物） | | 0.092 ✅ / 0.305 ✅ |
| 高光滚降 | P99.5 到 255 之间**留 10–25 个空档** | 全白会让纸纹消失 | 22 ✅ |

**怎么把"暗部面积"从 0.5% 拉到 2%**（这是我们最该做的调色动作）：
- 主因不是调色，是**墨的浓度**：`finish()` 里 `dInk = 1 - exp(-density * den.r)`，
  现在 `density = 1.65 × (1+0.10*pulse) × (1+0.05*bass)`。
  把干墨层的 alpha 从 0.30–0.46 提到 **0.42–0.60**，并把 `density` 提到 **2.4–2.8**，
  暗部面积会翻倍以上，且纸的白位基本不动（因为墨只占 5% 面积）。
- 加一条**墨芯提纯**：`dens = smoothstep(0.35, 0.95, dens)` —— 让中间调的洇层薄一点、
  墨芯实一点。参数：`smoothstep(lo, hi)` 的 `lo/hi` 在 0.30–0.45 / 0.85–0.98 之间试，
  目标是 P0.5 落到 25–40 而 P50 不掉。

### E.2 加"质感"的三个廉价手段（每个都能给参数）

| 手段 | 参数 | 代价 | 注意 |
|---|---|---|---|
| **颗粒 grain** | 幅度 **1.2–2.5/255**（≈0.005–0.010），**每帧重新随机**，且要**按亮度加权**（暗部颗粒重、高光几乎无颗粒）：`g *= (0.4 + 0.6*(1-lum))` | 编码码率 +5–10% | 固定图案的颗粒一动就露；必须每帧变 |
| **暗角 vignette** | `col *= 1 - v * smoothstep(0.34, 0.92, dist)`，`v = 0.12–0.20` | 0 | 超过 0.25 会像监控摄像头；我们是 0.17 ✅ |
| **轻微色差 / 通道偏移** | 只在**边缘**做：`offset = 0.35–0.8 px × smoothstep(0.45,0.95,dist)`，R 右移、B 左移 | 0 | 全画面统一偏移会糊；必须随半径加权 |
| （第四个，便宜的）**纸纹固定** | 纸纹用**屏幕坐标**采样，慢速漂移 ≤ 0.01 画面宽/秒 | 0 | **不要跟镜头走**——见 §E.3 |

### E.3 边沿软淡出：让"半截字"变成"字写到了纸外"

水墨/长卷这种"内容会跑出画框"的题材，边沿**不能硬切**——半截字贴着画面边缘是最扎眼的廉价感。
做法是把**墨密度**（不是最终颜色）在四边按距离淡出，纸底保持不动：

```glsl
dens *= smoothstep(0.000, 0.075, 1.0 - uv.y)   // 顶边 7.5%
      * smoothstep(0.000, 0.045, uv.y)         // 底边 4.5%
      * smoothstep(0.000, 0.075, uv.x)         // 左边 7.5%
      * smoothstep(0.000, 0.075, 1.0 - uv.x);  // 右边 7.5%
```

参数依据（都是实测）：`【实测·本片】`
- 顶边 7.5%：原来 69% 的帧有墨迹直接贴到画面最上一行（上一行被拦腰截断）。
  淡出带 ≥7% 后，越界帧降到 0。
- 左右 7.5%：先试 5%，改后仍有 12/80 帧墨迹压进左右 3% 安全带的 1.1–1.25%
  （红字尤其明显——朱砂在浅纸上 22% 不透明度仍然够暗）。放到 7.5% 才干净。
- 底边 4.5%：字幕是 DOM 元素，不在这层里，所以底边只需管墨。
  > **方向坑**：本项目 `uv.y = 1` 是**顶边**（世界 y 向上、屏幕 y 向下）。
  > 按直觉写成 `smoothstep(0, 0.07, uv.y)` 会把淡出放到**底边**去。

### E.4 一个必须修的 bug：纸纹"不可平铺"导致随镜头移动的硬色阶

`【实测·本片】` 全片每一帧都有一条**随镜头移动的硬横向色阶**：
- 位置：y = 0.30（t=2s）→ 0.24（t=15s）→ 0.20（t=40s），随镜头平移；
- 振幅：**6–12 / 255**（肉眼可见的"带状"）；
- 成因（第一版判断是错的，这里更正）：`paper.png` 本来就以 `REPEAT` 加载，
  真正的问题是**这张贴图不可平铺**——`REPEAT` 在 uv 整数边界把右边缘直接接上左边缘，
  两侧亮度差 4–14/255，于是形成一条**值不连续**的硬缝，随镜头扫过画面。

**修法（已验证，一行）**：`REPEAT` → `MIRRORED_REPEAT`。镜像在边界处左右翻转，
值**连续**，缝消失，且不需要重做贴图：
```js
const wrap = (repeat === 'mirror') ? gl.MIRRORED_REPEAT
           : (repeat ? gl.REPEAT : gl.CLAMP_TO_EDGE);
this.paperTex = await this._load('art/paper.png', 'mirror');
```
实测：最大台阶 **14.0/255 → 4.0/255（−71%）**，剩下的 3–4 级是纸纹自己的梯度。

验收方法（关键：**先把字全关掉**，否则量到的是文字行）：
```js
window.__flags = { noMasks: true, noLive: true, noBloom: true };
```
然后量相邻行中位亮度的孤立台阶，判据 **无 ≥4/255 的台阶**。

## F. 声音

### F.1 响度：先量，再决定增益

`【经验判断】` 目标值（流媒体通行做法，各平台会做整体响度归一，
所以**唯一该控的是 integrated LUFS 与 true peak**）：

| 内容 | Integrated | True peak | LRA |
|---|---|---|---|
| MV / 音乐为主 | **−14 LUFS ±1** | ≤ **−1.0 dBTP** | ≥ 3 LU |
| 竖屏口播（人声为主） | **−16 LUFS ±1** | ≤ **−1.5 dBTP** | ≥ 2 LU |
| 短影音（抢注意力） | −12 LUFS ±1 | ≤ −1.0 dBTP | ≥ 3 LU |

`【参考】` 各平台响度规范的汇总见
[RTW Loudness Standards](https://www.radioworld.com/tech-and-gear/rtw-publishes-list-of-loudness-standards)。

**我们的实测** `【实测·本片】`
- MV 样片：**−11.80 LUFS / TP +0.05 dBTP / LRA 2.90** → 偏响 2.2 LU，真峰值超线 1.05dB，有 2 个音频块贴 0 dBFS。
- 竖屏切片（4 条）：**−20.1 ~ −20.6 LUFS / TP −0.6 ~ −2.5** → 比目标**小 4.6 LU**，上传后会更小。
  **一边太响一边太轻，都是没过响度这一关。**

**修正命令（写进发布流水线）**
```bash
# 两步法：先两遍 loudnorm，得到"已归一"的文件
~/bin/ffmpeg -y -i in.mp4 -c:v copy \
  -af "loudnorm=I=-14:TP=-1.5:LRA=11:print_format=summary" \
  -c:a aac -b:a 192k out.mp4
# 再量一次确认（判据见 vaudio_check.py）
```

### F.2 MV 里"人声优先"的具体数字

| 素材 | 目标 | 做法 |
|---|---|---|
| 人声（vocals） | 相对**伴奏** +4 ~ +7 dB | 先定伴奏为 0，人声提到 −12 ~ −9 LUFS（短时窗口） |
| 伴奏（instrumental） | 整体比人声低 4–7 dB | 副歌可以让伴奏顶上来，但**人声要比伴奏高 ≥3 dB** |
| 最终混音 | −14 LUFS / TP −1.5 | 用 `loudnorm` 收口 |
| 削波 | 0 个音频块贴 0 dBFS | `astats` 每帧峰值必须 < −0.1 dBFS |

`【经验判断】` 判断"人声够不够"的土办法：把音量拧到"能听清歌词但有点吵"的位置，
再降到一半——**如果此时还能听清每个字，人声就够了**。

### F.3 画面跟鼓点，还是跟旋律？

| 情况 | 跟谁 | 具体参数 |
|---|---|---|
| 有鼓组、二分/四分律动的段落 | **跟鼓点（kick / snare）** | 画面事件对齐 `beat_time`；只在 **kick** 上做大变化（景别/亮度跳），snare 上做小变化（元素进出） |
| 只有旋律/弦乐/钢琴的段落 | **跟旋律（乐句起音）** | 对齐"音高起音时刻"，不必对齐拍；一个乐句（2–4s）一个事件 |
| 有长音 / 拖腔 | **反着来**：画面静止，让声音走 | 长音期间不做运镜，长音结束时给一次大事件 |
| 副歌爆发 | **跟鼓点，且加密** | 每 2 拍一次；连续最多 4 次后必须停一拍（否则失焦） |

`【实测·本片】` 我们的 `manifest.json` 已经有 319 个 `beat_times`（BPM 114.9）与
每句的 `t / end`，但**渲染代码里一次都没用它们做切点**——
`pushKey` 的时间全是 `row.t ± 0.02*dur`，与拍点无关。
最小改动：把 `pushKey(row.t - 0.02*dur, ...)` 换成
`pushKey(snap_to_beat(row.t, BEAT, 0.12), ...)`——把开始时刻吸附到 ±0.12s 内最近的拍点。
